                          └── CORE-P0-3 (关闭编排复位)

| **ENG-P0-1** | 工程化 | **建立 CI 主流水线**（push/PR 触发 → JDK21 + 缓存 → `mvn -B test`（一期）→ 归档报告 → 失败通知 → required status check） | PR 自动构建；失败阻止合并；二次构建 < 5min | **3** |

| **CORE-P0-1** | core | **切断 core 对 Serenity 编译期依赖**（`ConfigResolver` 接口 + SPI，Serenity 实现下沉 web） | core 依赖树无 serenity-*；无 Serenity classpath 可编译 | **3** |
| **CORE-P0-2** | core | **修复上下文线程模型**（ConcurrentHashMap + InheritableThreadLocal 开关 + 捕获/恢复 API + 禁新增 static ThreadLocal 的 ArchUnit 规则） | 子线程可继承/传递；并发读写单测通过 | **2** |

| **WEB-P0-1** | web | **修复共享 Browser 锁**（:690 / :742 改用 `browserLock(boolean)`） | 并发单测：N 线程共享 Browser 只创建一次 | **2** |

| **API-P0-1** | api | **消除全局配置串扰**（`ConfigProvider` 全局 volatile → per-thread `TestContext`） | 无静态可变 Config；N 线程不同 entity 并发互不影响 | **3** |
| **ROUTE-P0-1** | route | **断言失败必须置用例失败**（`HandlerExecutor` 显式上报 Serenity） | 故意配置失败断言 → 用例必须 FAIL 且报告可见 | **2** |
| **CG-P0-1** | codegen | **生成前冲突检测 + 安全写**（检测用户手工修改 → 拒绝覆盖 + diff + `--force`/`--backup` + 原子写） | 覆盖用户代码须显式确认；有 dry-run；失败不留半写文件 | **3** |

## 七、风险与依赖提示

| 风险 | 说明 | 缓解 |
|---|---|---|
| **CI 一开就红** | SpotBugs 空排除文件 + Checkstyle 存量违规，`mvn verify` 必然失败 | CI 一期只跑 `mvn test`；SpotBugs/Checkstyle 基线就位后再开全量 |
| **依赖下沉牵一发动全身** | core 去 Serenity 会影响 web/api/route 的传递依赖 | 先做 CORE-P0-1 接口下沉，再做 ENG-P0-2；每步 `mvn verify` 回归 |
| **拆上帝类无测试保护** | `PlaywrightManager`/`BasePage` 拆分本身会引入缺陷 | **先做 WEB-P0-2（DI seam + 可单测），再拆**；禁止无网作业 |
| **P0 修复并发进行易冲突** | 5 个 P0 均触及共享代码 | 按依赖图分批：CI → 4 个独立 P0 并行 → core 去 Serenity → 依赖下沉 |
| **整改与业务需求冲突** | 84 个任务 vs 日常用例开发 | 采用"最小可行整改集"（33 人日）先行，其余按季度滚动 |
